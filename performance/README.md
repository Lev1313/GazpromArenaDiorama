# Измерение производительности: legacy и Vite

Запуск: `npm.cmd run perf:compare`.
Команда сначала собирает production-версию, затем последовательно измеряет
оригинальный HTML и файлы из `dist/` через отдельные локальные HTTP-серверы.
Нужен установленный Microsoft Edge. Сцена и утверждённые PNG не изменяются.

## Методика этапа 5.2

- Edge headless, WebGL SwiftShader, 1400 × 850, DPR 1, одинаковые настройки цвета.
- Инициализация обеих симуляций вручную до t = 3 секунды (180 шагов 1/60 с),
  затем пауза. Пропуск отрисовки допускается только при этой подготовке.
- Во время измерений используются настоящие `requestAnimationFrame` и
  `performance.now`; каждый кадр отрисовывается. `gl.finish()` во время
  измерений не вызывается.
- Шесть ракурсов: общий, автосходка, арена, ЗСД, сверху, дрифт.
- По 10 прогревочных и 30 измеряемых кадров на ракурс в каждом запуске.
- Три повтора: legacy → Vite, Vite → legacy, legacy → Vite. Версии никогда
  не измеряются одновременно. Итого 90 измеряемых кадров на версию/ракурс.
- На время прогона желательно закрыть другие тяжёлые приложения и вкладки
  с анимированной диорамой. Инструмент не закрывает пользовательские вкладки.

## Что измеряется

- Вызовы рисования WebGL и количество переданных треугольников, включая
  дополнительные проходы теней. Это не число уникальных треугольников модели.
- Время выполнения RAF callback (медиана и p95). В него входят JavaScript,
  инструментация и возможное ожидание при отправке команд WebGL; поле
  `callbackCpuMs` сохранено из исходного инструмента, но это **не чистое CPU-время**.
- Интервал между RAF timestamp (медиана, p95, приблизительная частота).
  Это частота headless-браузера с программным WebGL, **не игровой FPS на GPU**.
- Стабильность числа вызовов рисования на всех кадрах и повторах.

Пауза исключает стоимость движения машин, вождения и обновления симуляции.
Эти результаты характеризуют статический рендер с обновлением HUD и камеры.
Они не измеряют время загрузки, рост памяти, GPU latency, мобильное устройство
или скорость активной сцены на видеокарте. Изменения времени в одном таком
эксперименте сами по себе не доказывают ускорение/замедление приложения.

## Результаты и воспроизводимость

`performance/_current/report.json` содержит исходные кадры каждого повтора,
итоговые метрики, сведения о CPU/ОС/Node/Edge, фактический WebGL renderer,
Git HEAD, состояние рабочего дерева и SHA-256 исходного HTML, инструмента
и файлов сборки. Интервалы не вычисляются между разными запусками.
`report.md` содержит две сводные таблицы.

Каталог `_current` игнорируется Git. Проверенный результат можно сохранить
в `performance/reports/` вместе с описанием условий. Это снимок измерений,
а не автоматически обновляемый эталон или строгий порог CI.

При ошибке процесс завершается с ненулевым кодом: не используйте оставшийся
от прошлого запуска отчёт как новый результат. Проверяйте `generatedAt` и
успешное завершение команды. Сравнение изображения остаётся отдельной
проверкой `npm.cmd run vite:verify`.
