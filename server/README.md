# Прогулка и совместные поездки — Stage 8A / 8B

Фронтенд остаётся статическим Three.js/Vite-приложением. WebSocket-сервер — отдельный процесс Node.js; он не запускается внутри Vercel. На этом этапе проверена локальная работа двух независимых клиентов. Хостинг и Production не менялись.

## Запуск на одном компьютере

Нужен Node.js 24 (на нём выполнены проверки). Из корня проекта:

```powershell
npm.cmd ci
npm.cmd run multiplayer:server
```

Сервер по умолчанию слушает `ws://127.0.0.1:8787/ws`. Проверка процесса: `http://127.0.0.1:8787/health`. Он хранит данные только в памяти и не пишет ники, адреса клиентов или сообщения в журнал.

Во втором терминале:

```powershell
npm.cmd run dev
```

Откройте адрес, который напечатал Vite (обычно `http://localhost:5173`), в двух отдельных вкладках/окнах или браузерах.

1. Первый игрок: **Два игрока** → адрес сервера → ник → **Создать комнату**.
2. Нажмите **Копировать ссылку** или скопируйте код из панели.
3. Второй игрок: откройте ссылку, нажмите **Два игрока**, задайте собственный ник и нажмите **Войти**. Ссылка только заполняет поля; сама по себе сетевое соединение не открывает.
4. Ходьба — WASD, Shift — быстрее, мышь — поворот камеры. Над персонажами видны ники, в панели — состояние подключения и число участников.
5. Подойдите к выбранной двери любой из 19 машин и нажмите **E**. Посадка завершается после подтверждения сервера. Водитель: WASD, пробел — ручник, C — камера; пассажир: собственная камера C, без управления машиной.
6. Остановитесь: **E / Esc** запрашивает безопасную высадку у своей двери. **R** доступна только подтверждённому водителю после остановки и возвращает его машину на свободное исходное место.
7. **Одиночный режим** выходит из комнаты. Чтобы присоединиться, находясь в одиночной машине, сначала остановитесь и физически выйдите.

Без подключения всё работает в прежнем одиночном режиме, включая 19 машин. В комнате заблокированы legacy-кнопка Golf и обзорные переходы: садитесь физически через E. Пока симуляция на паузе, посадка не начинается; снимите паузу перед E. Пауза останавливает только локальную физику, удалённые состояния продолжают обновляться. Автомобили и сиденья общие для комнаты. Трафик, автоматический дрифт и погода локальные. Дым/следы отображаются локально по движению/ручнику, их частицы не передаются.

Новая комната начинает с исходных парковочных мест; вход в существующую принимает её текущие 19 поз. После выхода машины сохраняют отображаемые положения в одиночной сцене. Комната не импортирует предыдущие одиночные поездки.

## Два компьютера в локальной сети

На компьютере с сервером замените пример IP на его адрес в вашей LAN:

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '8787'
$env:ALLOWED_ORIGINS = 'http://192.168.1.20:5173'
npm.cmd run multiplayer:server
```

В отдельном терминале запустите фронтенд:

```powershell
npm.cmd run dev -- --host 0.0.0.0 --port 5173
```

Оба игрока открывают `http://192.168.1.20:5173`, а в сетевой панели используют `ws://192.168.1.20:8787/ws`. Ссылка с `localhost`/`127.0.0.1` подходит только для клиентов на том же компьютере. Если порты недоступны из LAN, проверьте настройки вашей сети; скрипты проекта не изменяют правила брандмауэра.

`ALLOWED_ORIGINS` принимает точные origin через запятую, включая фактический порт Vite. Loopback-origin разрешены для локальной разработки. Клиенты без Origin допустимы для нативных тестов; проверка Origin не является авторизацией.

## Статический фронтенд и HTTPS

Опциональный `VITE_MULTIPLAYER_URL` задаёт начальный адрес поля сервера при сборке. Он не обязателен: на localhost используется локальный адрес, на остальных доменах поле остаётся пустым. Параметр `ws` в ссылке комнаты заполняет это же поле, но подключение всё равно требует нажатия кнопки.

На HTTPS-странице нужен `wss://…/ws`; браузер не должен подключаться к незащищённому `ws://`. Сам процесс Node обслуживает HTTP/WebSocket: для будущего публичного запуска потребуется отдельное решение для TLS/reverse proxy и эксплуатации. Оно здесь не развёрнуто, платные сервисы и настройки Vercel/Production не менялись.

## Протокол и ограничения

- Случайный roomId: 12 криптографических байт / 16 символов base64url (96 бит). Максимум два участника, включая временно сохранённые места. Третий получает `room-full`.
- playerId выдаёт сервер (UUID v4). Имя — 1–24 символа; управляющие символы запрещены. Ники отображаются через `textContent` и Canvas `fillText`, без HTML.
- Вход: JSON `{type:'create',v:1,nickname}` или `{type:'join',v:1,nickname,roomId}`. Сервер отвечает `welcome` с собственной сессией и списком участников. `roster` сообщает появление/выход, `pose` — только координаты, yaw и walking/moving.
- Клиент отправляет 10 walking-снимков/с и дополнительно до 10 vehicle-снимков/с только своего водительского места. Сервер проверяет точные схемы, конечные значения, диапазоны настройки машины, seq и владельца. Входящее сообщение <=1024 байт, серверный world ограничен клиентом 32 KiB (19 машин около 5 KiB); binary запрещён, сжатие выключено. Token bucket: 30 сообщений/с, burst 30. Некорректная схема закрывает сокет; игровой отказ сохраняет соединение и показывает причину.
- Ограничены комнаты (64), соединения (128), время первого сообщения (5 с), очередь медленного получателя (64 KiB). Heartbeat каждые 15 с удаляет неотвечающее соединение при следующей проверке; обнаружение потерянной сети может занять около 30 с.
- При разрыве персонаж исчезает после уведомления сервера. Место и случайный 192-битный ключ восстановления хранятся в RAM до 10 с. Ключ получает только собственный сокет; он не включается в ссылку, roster, снимки состояния или browser storage. Это временное восстановление соединения, без аккаунтов/логина.
- Клиент пробует переподключиться до пяти раз с задержкой 0.5–5 с. В пределах окна сохраняется playerId. После истечения сессии кнопка **Переподключиться** позволяет новый вход с новым ID; если ключ только что признан истёкшим, нажмите её ещё раз. Полная перезагрузка вкладки также начинает новый клиент; временно занятый слот освобождается после grace period.
- Явный выход освобождает место сразу. Пустые комнаты удаляются. Перезапуск сервера теряет все комнаты и сессии; после него создайте новую комнату.
- Удалённый персонаж — отдельный low-poly Group в существующей сцене, без контроллера ввода/камеры. Интерполяция по времени получения с буфером 120 мс, кратчайший поворот yaw, максимум 32 снимка. При пропуске пакетов поза удерживается без экстраполяции; анимация ног зависит от отображаемого перемещения.
- Владение сиденьями авторитетно на сервере; аркадная физика и коллизии мира — на клиенте водителя. Сервер проверяет владельца, значения и грубые ограничения перемещения, но не пересчитывает географию, ускорение и контакты. При задержках столкновения двух управляемых машин приближённые: каждый водитель видит интерполированного соседа. Удалённые пешие игроки косметические, без твёрдых коллизий. Сервер не проверяет скорость ходьбы; близость к двери проверяется по последней принятой пешей позе. Это не полноценная защита от читов.
- При отключении/выходе удалённые меши, материалы и текстуры имён освобождаются. Все комнаты и ники существуют только в памяти текущего процесса/страницы; нет базы, аналитики, аккаунтов и постоянного сохранения данных.

## Автомобили и сиденья — Stage 8B

Текущий клиент согласует `vehicles:true` при create/join. Старые walking-only клиенты без этой возможности сохраняют обмен позами, но не получают права на сиденья/машины. Лимит комнаты остаётся два игрока.

- `world` передаёт 19 поз и серверные таблицы сидений при входе/посадке/выходе/обрыве/сбросе. `vehicle` — принятый снимок конкретной машины: x/y/z/yaw, скорость, руль, ручник, signed distance передней/задней оси. Реальные колёса используют distance/radius; при ручнике задняя дистанция не меняется. GLB не клонируются/перезагружаются. Интерполяция 120 мс, до 32 состояний, без экстраполяции.
- `seat-enter`, `seat-exit`, `vehicle-reset` имеют общий возрастающий seq; `action-result` подтверждает/отклоняет запрос. Финальные сиденья берутся только из `world`. Занятость атомарная: один игрок — одно место. Проверяются известные vehicleId/seatId, роль, сокет/room/player и расстояние до двери <=1.2 м (локальная досягаемость .95 м). Выход: скорость <=.5 м/с, локально свободная точка своей двери; сервер проверяет её расстояние и внешнюю сторону кузова.
- Горизонтальная дистанция ограничена серверным временем dt (окно до .5 с): <=18*dt+.35 м, yaw <=6*dt+.2 рад, вертикаль <=4*dt+.35 м, изменение дистанции оси <=пройденная дистанция+.5 м. Произвольный телепорт отклоняется; машина возвращается к последней принятой позе и останавливается. R — отдельный запрос владельца после остановки. Сервер проверяет другие машины на исходном месте; клиент — также препятствия сцены.
- При обнаружении обрыва водителя сервер обнуляет скорость/руль, включает ручник и сохраняет последнюю принятую позу. Пассажир остаётся в машине. Место резервируется на 10 с; восстановленный сокет получает ровно его. После истечения резерва место освобождается; явный выход из комнаты освобождает сразу. Клиент при потере связи выключает водительский контроллер до подтверждения восстановления. Полный сетевой обрыв обнаруживается heartbeat примерно за 30 с.
- Водитель предсказывает свою физику без ожидания каждого кадра. Пассажир видит машину с сетевой задержкой; при коррекции возможен скачок к принятой позе. Сидящий персонаж привязан к отображаемой машине, а не к отдельному walking-снимку. Нет синхронизации AI, частиц, общего времени суток и паузы. Публичный сервер, полноценная авторитетная физика и комнаты на восемь игроков не реализованы.

## Проверки

```powershell
npm.cmd run build
npm.cmd run test:unit
npm.cmd run test:browser
```

Полный браузерный запуск включает прежний набор одиночного режима и `tools/multiplayer-browser.mjs` — отдельный реальный процесс сервера, два изолированных браузерных контекста, UI/клавиши, настоящий WebSocket-прокси с задержкой 200 мс в каждую сторону и повторные переподключения.

Отдельно:

```powershell
npm.cmd run test:multiplayer
npm.cmd run test:multiplayer:browser
```

Node-тесты используют настоящий сервер и клиенты: обмен состоянием, лимит комнаты, подмена ID, неверный формат, размер/частота, Origin, heartbeat, освобождение комнат и восстановление сессии. Проверки не меняют исходные модели и утверждённые визуальные baseline.

Финальный Stage 8B: build успешен, 149 unit / 489 одиночных / 106 сетевых браузерных проверок прошли. Все 19 машин проверены физической посадкой, движением и выходом; два клиента — общий GLA, пассажир/камера, колёса/ручник/задний ход, задержка 200 мс в обе стороны, конкуренция за место, восстановление водителя/пассажира и late join.
