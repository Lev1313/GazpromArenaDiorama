# Roadmap — Gazprom Arena Diorama

Обновлено: 2026-10-13. Активный план после первого публичного релиза.

## Концепция
Интерактивная low-poly территория Газпром Арены, постепенно развивающаяся из 3D-диорамы в автомобильную онлайн-площадку: автомобильная сходка, свободная езда и дрифт с друзьями, выход из машины и прогулки между автомобилями, рыбалка у воды, социальные взаимодействия и игровые помещения внутри стадиона.

Сохраняем узнаваемые ориентиры Петербурга (стадион, ЗСД, Лахта Центр), существующую стилистику и работоспособность текущего сайта.

## v1.0 — Публичная диорама — ГОТОВО
- [x] Модульная Three.js / Vite архитектура, GitHub и публикация на Vercel.
- [x] Газпром Арена, ЗСД, окружение и парковка.
- [x] День/ночь, фонари, фары, камеры и HUD.
- [x] 18 припаркованных автомобилей, включая красный Golf VI, RX Deep Blue Mica и GL X166 Obsidian Black.
- [x] Автоматический дрифт двух автомобилей с переменным заносом, контррулением, дымом и следами.
- [x] Уже есть управляемый Golf: клавиатура, ручник/занос, столкновения, камеры и экранные кнопки. Не реализовывать повторно.

## v1.1 — Публичная стабильность и производительность — СЛЕДУЮЩЕЕ
- [ ] Исправить/проверить атрибуцию всех внешних GLB, включая исходные ZIP с license.txt; добавить доступные посетителям credits.
- [ ] Измерить реальное время загрузки, FPS, draw calls и потребление памяти на десктопе и телефоне.
- [ ] Оптимизировать тяжёлый Lexus RX (~52 МБ, ~1.7 млн треугольников): облегчённая геометрия/LOD/сжатие, сохранив узнаваемый силуэт. Сравнить визуальный результат.
- [ ] Добавить аккуратное состояние загрузки/ошибки загрузки тяжёлых моделей; проверить ситуацию с медленным интернетом.
- [ ] Проверить опубликованную сборку с чистого браузера: машины, дневной/ночной режим, Golf, дрифт, мобильные элементы управления.
- [ ] Исправить только подтверждённые ошибки по результатам отзывов друзей.

**Готовность v1.1:** ссылка стабильно открывается на разных устройствах, модели появляются без ошибок; производительность и загрузка измерены, а не оценены на глаз. Новая версия не ухудшает основные функции.

## v1.2 — Свободная езда, персонаж и прогулки между машинами
- [ ] Улучшить текущие ощущения от езды Golf (руление, занос, газ/тормоз и камера преследования); сохранить управляемость на клавиатуре и телефоне.
- [ ] Добавить простого low-poly персонажа: перемещение пешком по парковке и тротуарам, поворот, базовые анимации ходьбы/ожидания, камера от третьего лица.
- [ ] Реализовать бесшовный режим «пешком ↔ за рулём»: подход к двери, кнопка взаимодействия (например, E), посадка/выход; нельзя выходить в препятствие или на ходу на высокой скорости.
- [ ] Ввести общую логику взаимодействий с ближайшим объектом (машина/скамейка/предмет/дверь), чтобы рыбалка и казино позднее использовали её повторно.
- [ ] Добавить пешие коллизии с припаркованными машинами, ограждениями, водой и препятствиями; не допускать застреваний, предусмотреть возврат персонажа в безопасную точку.
- [ ] Отделить визуальную модель автомобиля от его состояния и логики движения, чтобы менять автомобиль без копирования контроллера.
- [ ] Добавить простой выбор 2–3 управляемых автомобилей; не использовать тяжёлые статичные hero-GLB в качестве игровых моделей без оптимизации.
- [ ] Доработать столкновения/границы доступной для езды территории и безопасное возвращение автомобиля.
- [ ] Подготовить стабильное обновление состояния персонажа, автомобиля, посадки и высадки для будущей сетевой синхронизации; сервер пока не нужен.

**Готовность v1.2:** игрок может выйти из Golf, пройти между припаркованными автомобилями, снова сесть за руль, выбрать автомобиль и свободно ездить и дрифтить, не проходя сквозь машины/ограды.

## v1.3 — Первый мультиплеер (MVP)
- [ ] Выделить transport-neutral состояние игрока (id, режим пешком/за рулём, автомобиль, позиция, направление, скорость/ввод) и сериализацию.
- [ ] Добавить комнаты по приглашению: сначала 2 игрока, затем до 8 по результатам тестирования.
- [ ] Использовать отдельный WebSocket-сервис; Vercel продолжает размещать фронтенд, но не постоянный игровой WebSocket-процесс.
- [ ] Реализовать появление/выход игроков, ники над персонажами/машинами, плавную интерполяцию удалённых объектов и восстановление соединения.
- [ ] Синхронизировать движение машин, перемещение пешком и посадку/выход; не требовать на первом этапе сетевой физики столкновений между игроками. Дым/следы можно отображать локально.
- [ ] Протестировать задержки, разрывы соединения, права доступа к комнате и реальную производительность с 2–8 игроками.

**Готовность v1.3:** два друга могут открыть одну комнату, пройтись между машинами, сесть в автомобили и ездить вместе без заметных телепортаций.

## v1.4 — Прогулки и активности у воды — ПОЗЖЕ
- [ ] Рыбалка на берегу: безопасные точки доступа к воде, удочка, заброс, ожидание поклёвки и короткая мини-игра вываживания; набор виртуальных рыб и счёт улова.
- [ ] Использовать общий интерфейс взаимодействия из v1.2 (подойти → нажать E/кнопку → выполнить действие), а не писать отдельную систему управления для рыбалки.
- [ ] Предметы для атмосферы автомобильной встречи: виртуальная бутылка/банка пива, сигарета, анимации держать/пить/курить, локальные эффекты дыма и отдыха; только стилизованные игровые действия, без механических преимуществ, рекламы и продаж реальных товаров.
- [ ] При наличии мультиплеера отображать необходимые состояния предметов и анимаций у других игроков без сетевой синхронизации каждой частицы.
- [ ] Не снижать производительность из-за предметов, дыма, волн или дополнительных персонажей.

**Готовность v1.4:** игрок может дойти пешком до воды, порыбачить, а затем вернуться на парковку и использовать предметы автосходки; другие игроки видят основные действия.

## v2.0 — Стадион, казино и автомобильные встречи — ДОЛГОСРОЧНО
- [ ] Создать доступный через дверь компактный интерьер Газпром Арены — не моделировать весь стадион изнутри на первом шаге; поддержать переход с улицы и обратно.
- [ ] Добавить в интерьер стилизованное **казино** с интерактивными столами/автоматами (например, блэкджек, рулетка, слоты) и **исключительно виртуальными фишками без покупки за реальные деньги, вывода средств или призов**.
- [ ] Позднее синхронизировать нахождение друзей внутри помещения, их перемещение и участие в мини-играх; доступность через веб и ограничения устройств учитывать заранее.
- [ ] Расширить автопарк и кастомизацию цветов/дисков.
- [ ] Добавить фоторежим и совместные скриншоты.
- [ ] Добавить небольшие дрифт-испытания, счёт или лидерборды по желанию.
- [ ] Добавить больше интерактивных деталей парковки и окружающего района.

**Готовность v2.0:** стадион имеет рабочую небольшую внутреннюю игровую зону; на парковке доступны автомобильные и социальные активности, а казино использует только игровые фишки.

## Правила разработки
1. Один небольшой функциональный результат на задачу и отдельный PR; сначала короткий план, затем реализация.
2. По умолчанию экономная модель Codex; сложный режим только при необходимости. Избегать полного аудита, ненужных субагентов и повторных скриншотов.
3. Перед merge: тематические тесты, production build, короткая браузерная проверка, если менялся визуальный или игровой код.
4. Не перезаписывать одобренные визуальные эталоны без явного подтверждения.
5. Не ломать опубликованную версию: изменения вливаются в master после проверки; Vercel обновляется из production-ветки.
6. PROGRESS.md — журнал выполненной работы, CONTEXT.md — контекст проекта, этот ROADMAP.md — актуальные планы. Исторические разделы сохраняем.
