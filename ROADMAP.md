# Roadmap — Gazprom Arena Diorama

Обновлено: 2026-10-13. Активный план после первого публичного релиза.

## Концепция
Интерактивная low-poly территория Газпром Арены, постепенно развивающаяся из 3D-диорамы в автомобильную онлайн-площадку: прогулка камерой, автомобильная сходка, свободная езда и дрифт с друзьями.

Сохраняем узнаваемые ориентиры Петербурга (стадион, ЗСД, Лахта Центр), существующую стилистику и работоспособность текущего сайта.

## v1.0 — Публичная диорама — ГОТОВО
- [x] Модульная Three.js / Vite архитектура, GitHub и публикация на Vercel.
- [x] Газпром Арена, ЗСД, окружение и парковка.
- [x] День/ночь, фонари, фары, камеры и HUD.
- [x] 18 припаркованных автомобилей, включая красный Golf VI, RX Deep Blue Mica и GL X166 Obsidian Black.
- [x] Автоматический дрифт двух автомобилей с переменным заносом, контррулением, дымом и следами.
- [x] Уже есть управляемый Golf: клавиатура, ручник/занос, столкновения, камеры и экранные кнопки. Не реализовывать повторно.

## v1.1 — Публичная стабильность и производительность — СЛЕДУЮЩЕЕ
- [ ] Исправить/проверить атрибуцию всех внешних GLB, включая исходные ZIP с license.txt; добавить доступные посетителям credits.
- [ ] Измерить реальное время загрузки, FPS, draw calls и потребление памяти на десктопе и телефоне.
- [ ] Оптимизировать тяжёлый Lexus RX (~52 МБ, ~1.7 млн треугольников): облегчённая геометрия/LOD/сжатие, сохранив узнаваемый силуэт. Сравнить визуальный результат.
- [ ] Добавить аккуратное состояние загрузки/ошибки загрузки тяжёлых моделей; проверить ситуацию с медленным интернетом.
- [ ] Проверить опубликованную сборку с чистого браузера: машины, дневной/ночной режим, Golf, дрифт, мобильные элементы управления.
- [ ] Исправить только подтверждённые ошибки по результатам отзывов друзей.

**Готовность v1.1:** ссылка стабильно открывается на разных устройствах, модели появляются без ошибок; производительность и загрузка измерены, а не оценены на глаз. Новая версия не ухудшает основные функции.

## v1.2 — Управление и автомобильная песочница
- [ ] Улучшить текущие ощущения от езды Golf (руление, занос, газ/тормоз и камера преследования); сохранить управляемость на клавиатуре и телефоне.
- [ ] Отделить визуальную модель автомобиля от его состояния и логики движения, чтобы менять автомобиль без копирования контроллера.
- [ ] Добавить простой выбор 2–3 управляемых автомобилей; не использовать тяжёлые статичные hero-GLB в качестве игровых моделей без оптимизации.
- [ ] Доработать поведение столкновений/границы доступной территории и безопасное возвращение машины в исходную точку.
- [ ] Подготовить стабильный цикл обновления физики и интерфейс состояния автомобиля для будущей синхронизации, но пока без сервера.

**Готовность v1.2:** один игрок может выбрать автомобиль, свободно ездить и дрифтить без конфликтов с автотрафиком и статичной сценой.

## v1.3 — Первый мультиплеер (MVP)
- [ ] Выделить transport-neutral состояние игрока (id, автомобиль, позиция, направление, скорость/ввод) и сериализацию.
- [ ] Добавить комнаты по приглашению: сначала 2 игрока, затем до 8 по результатам тестирования.
- [ ] Использовать отдельный WebSocket-сервис; Vercel продолжает размещать фронтенд, но не постоянный игровой WebSocket-процесс.
- [ ] Реализовать появление/выход игроков, ники, плавную интерполяцию удалённых машин и восстановление соединения.
- [ ] Синхронизировать движение, но на первом этапе не требовать сетевой физики столкновений между игроками; дым и следы можно отображать локально.
- [ ] Протестировать задержки, разрывы соединения, права доступа к комнате и реальную производительность с 2–8 игроками.

**Готовность v1.3:** два друга могут открыть одну комнату и одновременно видеть, как каждый управляет машиной, без заметных телепортаций.

## Правила разработки
1. Один небольшой функциональный результат на задачу и отдельный PR; сначала короткий план, затем реализация.
2. По умолчанию экономная модель Codex; сложный режим только при необходимости. Избегать полного аудита, ненужных субагентов и повторных скриншотов.
3. Перед merge: тематические тесты, production build, короткая браузерная проверка, если менялся визуальный или игровой код.
4. Не перезаписывать одобренные визуальные эталоны без явного подтверждения.
5. Не ломать опубликованную версию: изменения вливаются в master после проверки; Vercel обновляется из production-ветки.
6. PROGRESS.md — журнал выполненной работы, CONTEXT.md — контекст проекта, этот ROADMAP.md — актуальные планы. Исторические разделы сохраняем.
