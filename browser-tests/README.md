# Этап 5.3: функциональные браузерные проверки Vite

Запуск: `npm.cmd run test:browser`.

Инструмент `tools/vite-functional.mjs` собирает отдельный production bundle
в `browser-tests/_current/dist/`, поднимает временный HTTP-сервер и запускает
установленный Microsoft Edge с WebGL SwiftShader. Исходники приложения,
обычный каталог `dist/`, legacy и визуальные эталоны не изменяются.

## Что проверяется

В текущей версии **59 проверок**, четыре независимых браузерных контекста:

- Сцена: количество объектов/контролов, фактическое движение ЗСД и двух
  дрифтеров, дым и следы, замораживание симуляции на паузе, шесть пресетов,
  вращение мышью и масштабирование колесом, реальные параметры света и
  тумана, выключение/возврат дыма, темп 0,3/1/2, фотоисточники, resize.
- Трафик: полный цикл первого гостя «въезд → парковка → выезд → ожидание»,
  соответствие счётчика фактическим припаркованным гостям, длительная
  симуляция с ограниченными буферами (90 частиц, 4000 сегментов следов)
  и постоянным числом объектов верхнего уровня сцены.
- Golf: вход и HUD, пауза/сброс клавиш, три камеры, физическое перемещение,
  W/A/D/Space/S, остановка, следы торможения, столкновение и выезд задним
  ходом, R, стрелки, очистка клавиш при blur/скрытии документа, защита от
  управления при вводе в поле, Esc и восстановление камеры/машины,
  независимость ускорения Golf от темпа сцены.
- Мобильный режим: видимость педалей, браузерные touch-события через CDP,
  газ и руль двумя пальцами, отпускание и отмена касания, задний ход,
  кнопки сброса/камеры/выхода, изменение размера на горизонтальный экран.

Проверки подтверждают состояние сцены и машин, а не только подписи кнопок.
Фотоисточники проверяются как ссылки, внешние сайты не открываются.

## Изоляция и ограничения

Vite-плагин только для тестовой сборки добавляет `window.__readDiorama()`
в точку входа. Функция возвращает копию состояния через JSON: ссылки на
изменяемые объекты и методы контроллеров наружу не выдаются. Все действия
выполняются через DOM, клавиатуру, мышь или браузерные touch-события.
Обычный `npm.cmd run build` этого плагина не использует; отсутствие
`__readDiorama` в обычной сборке проверено отдельно.

Clock фиксирован на 1/60 с. Промежуточные WebGL draw calls при ускоренной
симуляции пропускаются, но логика, обновление буферов и последний видимый
кадр выполняются. Этот набор не измеряет FPS или время выполнения кадра.

`blur` и `visibilitychange` проверяются управляемой отправкой событий,
включая временную подмену `document.hidden`. Это проверка обработчиков,
не тест переключения окон ОС. Мобильное устройство эмулируется в Edge,
это не испытание физического телефона. Проверка постоянства объектов
не заменяет профилирование памяти. Геометрические пограничные случаи и
математика уступания дороги дополнительно покрываются `test:core`;
не заявляется исчерпывающее покрытие всех возможных траекторий движения.

## Отчёты

`browser-tests/_current/report.json` содержит результат каждого assert,
ошибки, версию браузера и список четырёх диагностических PNG. При ошибке
сохраняется дополнительный кадр, `ok=false`, процесс завершается с кодом 1.
Все генерируемые файлы `_current` игнорируются Git; сохранённые результаты
конкретных прогонов находятся в `browser-tests/reports/`.

Диагностические PNG не являются новыми визуальными эталонами. Принятые
эталоны отдельно проверяются через `npm.cmd run vite:verify`; неизменённый
оригинал — через `npm.cmd run baseline:verify`.

## Stage 7A — прогулка

`npm.cmd run test:pedestrian` проверяет движение при 15/30/60/144 FPS,
диагонали, Shift, реальные размеры Golf/Lexus/Mercedes, тонкие ограды,
скольжение, берег, высоту земли, динамические препятствия и переходы
между существующим Golf и прогулкой.

`npm.cmd run test:pedestrian:browser` запускает только новый сценарий
в настоящей сцене Edge/SwiftShader. `test:browser` включает его вместе
с существующими сценариями. Проверяются вход/выход, WASD/Shift, анимация,
пауза, три GLB, скольжение, поворот камеры мышью, день/ночь, пресеты,
переключение Golf/прогулка, blur и безопасный возврат. Начальные точки
рядом с тремя GLB задаёт отдельный test-only fixture; столкновения
проверяются настоящими нажатиями клавиш. В обычной production-сборке
нет ни fixture, ни snapshot API. Ожидание загрузки использует таймеры,
поскольку тестовые RAF-часы намеренно остановлены.

Пять `pedestrian-*.png` — снимки для ревью, не утверждённые эталоны.
Ходьба пока требует клавиатуру; камера поддерживает перетаскивание сцены.
Дополнительно проверяются настоящая парковочная ограда, скольжение вдоль
неё, граница острова и высота поднятого тротуара относительно травы.

## Stage 7B — посадка в конкретный автомобиль

`npm.cmd test` теперь запускает все unit-тесты (`test:unit`), затем полный
набор Edge/SwiftShader (`test:browser`). `test:seating` запускает реестр
мест, физическую высадку Golf и интеграционные тесты персонажа/режимов.
`test:seating:browser` оставляет только сценарий посадки.

Проверяются 18 стабильных vehicleId, четыре места на машину, повторное
занятие места, стороны/роли, car.localToWorld с родительскими преобразованиями,
замена GLB без потери ID, реальная поза одного персонажа, высадка у двери,
препятствия/скорость, все способы выхода, R и прежний обзорный режим Golf.
После физической высадки Golf остаётся препятствием для существующего
уступающего трафика/дрифта до сброса или освобождения пути.

Браузерные действия используют настоящие E/Esc/C, WASD, ручник и кнопки.
Private build задаёт только начальные позиции у дверей; для отказов
использует fixtures занятости и полностью перекрытой зоны высадки.
Нет этих hooks в обычной dist. Участки ограды и берега проверяет также
предыдущий сценарий прогулки. Скриншоты `seating-*.png` — отдельное ревью,
без изменения утверждённых baseline. Места и позы стилизованы; открывание
дверей, второй видимый игрок и сетевой сервер не реализуются в этом этапе.
